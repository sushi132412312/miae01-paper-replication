## 1. 你刚读完的脚本起什么作用

roberta_base_sst2.sh主要是一张“实验设置单”：指定模型、任务、批次、轮次、学习率、LoRA开关、种子和输出目录。

脚本把这些设置交给run_glue.py。后者负责把数据、模型、训练器和评估连接起来。

~~~mermaid
flowchart TD
    A["启动脚本<br/>列出实验设置"]
    B["run_glue.py<br/>读取设置和随机种子"]
    C["加载影评数据、分词器和预训练模型"]
    D["决定更新哪些参数<br/>普通层或LoRA层"]
    E["文本变成数字编号<br/>选训练集与验证集"]
    F["训练器执行学习<br/>评估并保存指标"]
    G["三种子统计、扩展分析<br/>报告与GitHub证据"]
    A --> B --> C --> D --> E --> F --> G
~~~

## 3. 文本怎样进入模型

以“这部电影很好看”的英文表达作为教学示意。数据里有影评文本及正确的正/负标签。

1. 分词器先把文本拆成模型认识的单位，再变成数字编号。
2. 模型内部把数字编号变成数值表示，逐层计算。
3. 分类头给出两个类别的分数。
4. 预测时选择分数较高的类别，与正确标签比较。

分词器产生的编号不是准确率。两个类别的原始分数也不必已经是概率。准确率来自最终预测和正确标签的比较。

## 4. “训练”里发生什么

程序一次拿一个小批次样本，计算预测和正确标签之间的损失，再反向计算梯度，由优化器更新允许训练的参数。重复完成一轮数据后，称为一个epoch。

FT与LoRA的关键差别在于允许更新的参数范围。评估阶段查看验证数据并计算指标，不进行同样的参数更新。

训练损失下降是过程信息；最终任务表现仍需要看验证结果和跨种子统计。

## 5. 今天已经找到的三项具体事实

- 原SST-2脚本没有设置max_train_samples。max_seq_length=512限制的是单条文本长度，不表示训练样本只有512条。
- LoRA线性层的实际语句把A做Kaiming均匀初始化、B置零，和论文描述的A高斯初始化存在差异；邻近的一条旧注释还把A/B初始化方向写反了。
- 主程序明确保存训练和评估的汇总指标；本次检查的do_eval代码块没有显式保存逐例验证预测。本组如采用逐例复算的验收方式，需要补充该导出能力或选用已具备该能力的实现。

这些是源码检查结论，不是训练效果结论。初始化差异是否影响准确率，需要受控实验；代码注释不能替代实际运行证据。
