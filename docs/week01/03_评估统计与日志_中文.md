## 1. 模型分数怎样变成准确率

run_glue.py 515-526行定义评价方法。分类任务先用argmax选择分数较高的类别，再交给任务指标计算函数，与正确标签比较。

人工示例：三个样本预测为[1,0,1]，正确标签为[1,0,0]，答对2个，准确率为2/3，约66.667%。这只是解释计算方式，不是模型实验结果。

## 2. 三个种子怎样汇总

人工准确率例子为[80,82,84]%，均值为82%，样本标准差为2个百分点。计算样本标准差时，方差的分母使用n-1。它与总体标准差不同。

如果对应噪声条件为[79,80,83]%，逐种子下降是[1,2,1]个百分点，平均下降约1.333个百分点、样本标准差约0.577个百分点。配对下降应先逐种子相减，再计算均值和标准差。

这里所有数字均为人工教学示例，应与研究结果分开。助手执行的statistics核对记录保留了输入、计算结果及示例标签。

### 2. 我独立核对得到的结论

**（1）`max_val_samples` 不是随机抽样，而是取数据集顺序的前 N 条。**
第 492–493 行：

```python
if data_args.max_val_samples is not None:
    eval_dataset = eval_dataset.select(range(data_args.max_val_samples))
```

训练集（485–486）与测试集（499–500）也是同样的 `select(range(N))`。因此：
- 只改训练种子而不改 `max_val_samples`，验证集保持为同一批样本；这不会消除训练初始化、数据顺序和 dropout 等随机性，不能据此判断“不构成多种子重复”。
- 本组建议固定训练子集和验证集，改变训练随机种子 42、43、44；不要求为每个种子重新切分验证集。需要核对训练随机源确实被种子控制。

**（2）`do_eval` 只保存聚合指标，没有逐例记录。**
第 571–589 行在 `trainer.evaluate()` 之后只有 `trainer.log_metrics("eval", ...)` 和
`trainer.save_metrics("eval", ...)`。`save_metrics` 的实现位于
`examples/NLU/src/transformers/trainer_pt_utils.py`（`trainer.py` 通过
`from .trainer_pt_utils import ... save_metrics ...` 引入），核心两行是：

```python
path = os.path.join(self.args.output_dir, f"{split}_results.json")
...
if combined:
    path = os.path.join(self.args.output_dir, "all_results.json")
```

因此评估产物是 **`eval_results.json`**（`{split}_results.json`，`split="eval"`），
并会合并写入 **`all_results.json`**；两个文件里只有聚合指标，没有样本 ID、金标签、预测标签。

补充：MNLI 任务下，第 578–589 行会对 matched / mismatched 各调用一次
`trainer.save_metrics("eval", ...)`，两次写同一个 `eval_results.json`，
后一次覆盖前一次；两者的合并结果只保留在 `all_results.json` 中。

**（3）`compute_metrics` 同样不落盘逐例结果。**
第 515–526 行：先 `np.argmax(preds, axis=1)`，再交给 `metric.compute(...)`，
只返回 accuracy / combined_score 这类标量。

**（4）`do_predict` 的输出文件不能用来复算准确率。**
第 591–617 行虽然写了 `test_results_<task>.txt`，但：
- 第 603 行先执行 `test_dataset.remove_columns_("label")`；
- 第 611–617 行只写 `index\tprediction`。

没有金标签，就无法从这个文件复算出准确率。

**结论：**如果验收要求“能从记录复算准确率”，官方脚本在当前配置下**不满足**，
必须自己增加逐例导出（样本 ID / 金标签 / 预测标签），或在复现实现里另行保存。

### 3. 教学例子复算（与文档正文对照）

| 例子 | 计算 | 结果 | 与正文是否一致 |
|---|---|---|---|
| 预测 [1,0,1]，标签 [1,0,0] | 答对 2 个 / 共 3 个 | 2/3 = 66.667% | 一致 |
| 三个种子 [80,82,84]%（样本标准差，分母 n−1） | 均值 82，标准差 2 | 82 ± 2 | 一致 |
| 配对下降 [1,2,1] 个百分点 | 均值 4/3，样本标准差 0.577 | 1.333 ± 0.577 | 一致 |

注意：样本标准差分母用 `n−1`。若误用总体标准差（分母 `n`），上例会得到 1.633 和 0.471，
两种口径不能混用；报告里必须写明用的是哪一种。

### 4. 对我们正式复现的要求（据此确定实现口径）

1. 每轮评估必须导出逐例记录：样本 ID、金标签、预测标签、所用随机种子；
2. 训练子集如需缩小，使用独立的固定子集种子抽取一次并记录；所有训练种子与方法共用该子集及同一验证集。验证集可采用完整划分；若缩小则固定选择方式并说明局限，不按训练种子重新切分。
3. “均值 ± 标准差”由外部脚本从逐例记录聚合，原始记录随每次运行保存；
4. 报告中的 Paper vs Ours 必须标注统计口径（种子数、样本数、指标实现）。

## 2026-11-15 修订说明（AI辅助，本人已复核）

本次保留“`select(range(N))` 是取前 N 条”的源码事实，更正“固定验证集无法做多训练种子实验”的错误推论。固定数据与评估对象、改变训练随机性，有助于隔离训练波动；同时更换验证子集会混入评估样本变化。参见 [Dodge 等对初始化和数据顺序随机性的研究](https://arxiv.org/abs/2002.06305)。

新增的代码检查使用人工样本和随机初始化的小 RoBERTa，不是 SST-2 或 RoBERTa-base 的实验成绩。正式训练设置仍待组长确认。
