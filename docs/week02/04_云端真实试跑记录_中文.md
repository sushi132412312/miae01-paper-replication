# 云端真实工程试跑记录（2026-11-15）

**这次真实跑通了RoBERTa-base／SST-2的FT与LoRA流程；还不是正式三种子论文复现。** 本文随代码提交配置、运行日志、逐例预测和复算结果，成员对本次云端记录的审核意见在PR中保留。

## 本次确认的设置

- GPU：NVIDIA GeForce RTX 4090，实际可见显存约23.64GiB；CUDA运算与反向传播通过。
- Python 3.10.16、PyTorch 2.7.1+cu126、Transformers 4.57.3、Datasets 4.4.1、NumPy 1.26.4。
- 预训练模型：FacebookAI/roberta-base，revision `e2da8e2f811d1448a5b465c236feacd80ffbac7b`。
- 数据：nyu-mll/glue中的SST-2，revision `bcdcba79d07bc864c1c254ccfcedcce55bcc9a8c`。
- 固定训练子集64条、固定验证子集64条；subset_seed=2026，train_seed=42。
- 每种方法10个优化器更新步，batch=2，最大文本长度128，FP32。
- FT学习率2e-5，LoRA学习率5e-4，weight_decay=0.1；LoRA仅q/v，rank8、alpha8。
- 使用末步预测，不选最佳轮次。64条是候选训练子集，10步×2条实际只见到20条训练样本；验证64条全部评估。

服务器不能直连Hugging Face，实际通过 `https://hf-mirror.com` 获取相同固定版本。下载来源与大文件SHA256见执行记录；数据缓存、预训练权重不进入交付包或GitHub。

## 这些准确率说明什么

**两种方法本次都将64条验证样本预测为0。** 金标签中有34条0、30条1，因此53.125%等于常数类别基线。本次尚未展示超过该基线的分类效果，不能据此宣称LoRA和FT效果相当，或已经复现论文准确率。

本次只做了10步、一个种子，主要验证流程。不能未经控制实验就把现象归因于某一个学习率、数据规模或LoRA参数。正式阶段仍需锁定更完整预算、至少三个种子、一项扩展和证据支持的分析；此处不报告均值±标准差。

## 通过的核查

训练数据、验证数据、共同主干初值、新分类头初值、更新步数与训练样本顺序均配对一致；LoRA初始化B为零，训练后冻结主干权重不变。两份预测均已在本机用不依赖PyTorch的标准库工具复算，结果与云端指标一致。最终版本的26项代码检查全部通过。

训练更新循环计时约FT 0.858秒、LoRA 0.815秒；这是很短的工程检查，不能作为正式速度基准。总流程计时分别约72.74秒、19.18秒，包含下载、加载、缓存与核验，不能用总流程时间宣称某方法快几倍。显存指标是PyTorch张量分配峰值，不含全部驱动与运行库开销，也不是最低显存配置保证。

本入口未保存可重载的训练后权重；预测中的checkpoint字段是末步模型状态校验标识，不是可下载权重文件。

## 运行和证据

在匹配CUDA的环境中安装PyTorch2.7.1及 `requirements.cloud.txt`，再执行以下命令；使用新的输出目录，避免覆盖已有记录：

```bash
export HF_ENDPOINT=https://hf-mirror.com
export HF_HUB_DISABLE_XET=1
export CUBLAS_WORKSPACE_CONFIG=:4096:8
python -m src.train --config configs/pilot.approved.20261115.json --method ft --output local_runs/recheck_ft --device cuda
python -m src.train --config configs/pilot.approved.20261115.json --method lora --output local_runs/recheck_lora --device cuda
python tools/recompute_metrics.py --predictions local_runs/recheck_ft/predictions.csv --manifest local_runs/recheck_ft/validation_manifest.json
```

预期是各10步、各64条完整预测与可复算指标。跨硬件或版本的准确率以实际记录为准，不承诺逐位相同。

本次为复用预装GPU镜像创建了独立虚拟环境；系统Python与镜像PyTorch解释器不同。项目中将typing_extensions固定为4.13.2，解决镜像Selenium的已有约束，未覆盖镜像的PyTorch或驱动。完整版本快照为 `requirements.cloud.lock.txt`。
