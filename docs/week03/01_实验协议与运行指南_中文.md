# RoBERTa-base／SST-2 实验协议和运行指南

本次锁定比较对象为 RoBERTa-base 在 SST-2 上的全参数微调和 LoRA。用同一指标 `accuracy = 答对数 / 验证样本数`，检查 LoRA 对可训练参数量的影响，并比较两个方法在课程缩小设置下的准确率。取每次运行验证准确率最高的一轮，同分取最早一轮。每种方法完成 42、43、44 三个种子后报告均值和样本标准差，再按种子计算 LoRA − FT，单位为百分点。

## 单因素扩展提案

研究问题是训练标签受扰时，两种方法的验证准确率分别下降多少。主实验保持原始标签。扩展只用 `label_noise_seed=2027` 从同一批训练样本抽取固定 ID，把其二分类标签 0 与 1 对调。候选 512 条中翻转 51 条，约 10%。固定模型版本、样本 ID、验证标签、种子、批次、每种方法学习率、轮数和选轮规则。逐种子计算各方法的干净 − 翻转条件准确率，再汇总均值和样本标准差。

`subset_seed` 固定用于抽样，`train_seed` 控制训练初始化和样本顺序，`label_noise_seed` 固定用于选择翻转的训练标签。数据清单记录翻转的样本 ID 和原始清单摘要。

## 组长定稿后执行真实实验

选择 CUDA 资源，使用教案允许的子集规模，锁定主实验配置。单独保存确认后的 `configs/reduced_scale.clean.json`，状态使用 `approved_reduced_scale`。扩展配置以同一文件生成，只改变 `train_label_flips`。组员分别用 42、43、44，给每次运行独立目录名。

云端使用 Python 3.10 和对应 CUDA 的 PyTorch 2.7.1，核对 [云环境锁文件](../../requirements.cloud.lock.txt)。在匹配 CUDA 12.6 的环境可从 PyTorch 的 cu126 索引装对应构建，再按锁文件安装复用的依赖。使用 `python tools/check_cloud_environment.py --output local_runs/cloud_environment.json` 检查 CUDA 计算和反向传播。下载模型和数据使用 JSON 中的完整 revision，模型、数据缓存与权重留在运行机器。

```bash
export CUBLAS_WORKSPACE_CONFIG=:4096:8
python -m src.train --config configs/reduced_scale.clean.json --method ft --train-seed 42 --device cuda --output local_runs/clean_ft_seed42
python -m src.train --config configs/reduced_scale.clean.json --method lora --train-seed 42 --device cuda --output local_runs/clean_lora_seed42
python -m src.replay --run local_runs/clean_lora_seed42 --output local_runs/clean_lora_seed42_replay.json
```

这组 CUDA 命令随配置定稿后验证。本机已完成 CPU 合成复核。运行结束后对每个种子的两个方法回读并复算，给 `src.paired` 传入所有运行目录。正式主实验用六次运行，两个条件一起汇总时用十二次运行。缺配对时汇总显示缺项清单。
