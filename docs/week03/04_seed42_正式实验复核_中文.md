## 一、复核内容

1. 从 `epochs/00X/predictions.csv` + `validation_manifest.json` 重算每轮准确率（每轮 872 条）；
2. 按"验证准确率最高、同分取最早"复算最佳轮次，与 `checkpoint_selection.json` / `metrics.json` 比对；
3. clean 与 noise 的训练清单比对，确认只差 51 条标签；
4. 同条件下 FT 与 LoRA 的初值哈希、训练/验证选择哈希、步数比对；
5. 与 `paired_summary_all_seeds.json` 的 seed42 行对齐。

## 二、结果

| 运行 | 最佳轮次 | 验证答对 | 准确率 | 与记录 |
|---|---:|---:|---:|---|
| clean_ft_seed42 | 3 | 779 / 872 | 89.3349% | 一致 |
| clean_lora_seed42 | 3 | 777 / 872 | 89.1055% | 一致 |
| noise_ft_seed42 | 3 | 759 / 872 | 87.0413% | 一致 |

- 12 个轮次全部与 `checkpoint_selection.json`、`metrics.json` 一致，`problems` 为空；
- clean 与 noise 训练清单样本 ID、顺序相同，**恰好 51 条标签不同**；
- FT 与 LoRA 的主干初值哈希、分类头初值哈希、训练与验证选择哈希、步数（192）一致；
- 四个数值与 `paired_summary_all_seeds.json` 的 seed42 行完全一致。

## 三、与 seed44 的对照

| 条件 | seed42 | seed44 |

这与组内汇总里 noise-FT 样本标准差 2.38 个百分点相符。

## 四、局限

1. **只复核种子 42**；种子 43 的逐例记录不在本次 PR 中，其数值以组内汇总为准；
2. **权重未回读**：云端 `.safetensors` 不在仓库，只有 `checkpoint_selection.json` 中的大小与 SHA-256；
3. **口径差异**：512 训练 / 872 验证 / 3 轮、FT 2e-5 与 LoRA 5e-4，与论文 Table 2 不同，不能直接并列；
4. 本复核不重新训练，只验证"记录 → 复算"这一层。

## 五、结论

种子 42 的四次运行记录自洽、可复算，逐轮准确率与选轮结果均与记录一致，
51 条标签翻转与 FT/LoRA 配对符合设计。同意合并（已在 PR #7 上给出 APPROVE）。
